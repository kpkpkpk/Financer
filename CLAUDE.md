# Finance Tracker — Техническое задание

## 1. Описание проекта

**Finance Tracker** — мобильное приложение для учёта личных финансов (доходы/расходы) на базе Kotlin Multiplatform (Android + iOS). Интерфейс на русском языке, валюта — рубли (₽).

Ключевая идея: простое приложение без серверной части. Все данные хранятся локально на устройстве.

---

## 4. Экраны и функциональность

### 4.1. Онбординг (✅ реализован)

- Иллюстрация, приветственный текст, кнопка «Начать»
- Показывается один раз, статус сохраняется в Preferences

### 4.2. Главный экран (Home)

**Верхняя часть:**
- Общий баланс (крупным шрифтом): итоговая сумма всех доходов минус расходов
- Карточка-сводка: доход / расход за выбранный период
- Иконка фильтра (воронка) — открывает экран выбора периода (см. 4.6)
- Текстовая метка текущего фильтра (напр. «Этот месяц» или «1 апр — 26 июн»)

**Список транзакций:**
- Группировка по датам (заголовок-дата)
- Каждая транзакция: эмодзи-иконка категории, название категории, время, сумма (зелёная для дохода, красная/чёрная для расхода)
- **Тап на транзакцию** → открывает экран редактирования (см. 4.5)
- **Свайп для удаления** → диалог подтверждения «Удалить транзакцию?» с кнопками «Удалить» / «Отмена»
- Примеры: 🍔 Еда -2 678 ₽, 🚗 Транспорт -1 356 ₽, 💰 Зарплата +40 300 ₽

**Empty state (нет транзакций):**
- Иллюстрация/иконка
- Текст: «Пока нет записей»
- Кнопка: «Добавить первую транзакцию» → открывает экран добавления

### 4.3. Аналитика и статистика (Insights — единый экран)

Один экран с переключателем вверху: **Статистика** / **Аналитика** (сегментированная кнопка или табы).

#### Вкладка «Статистика»

**Верхняя часть:**
- Два чипа: «Общий расход» (розовый) и «Общий доход» (зелёный) с суммами
- Переключатель периода: Неделя / Месяц / Год
- Текстовая метка текущего диапазона дат (напр. «16 июня — 23 июня»)
- Итоговая сумма за период (напр. -34 466 ₽)

**Графики (Bar Chart):**
- **Неделя**: столбцы по дням (Пн—Вс), каждый столбец = сумма расходов/доходов за день
- **Месяц**: столбцы по дням (1—28/29/30/31)
- **Год**: столбцы по месяцам (Янв—Дек)
- **Тап на столбец** → tooltip с точной суммой за этот период

**Под графиком:**
- Список транзакций за выбранный период (аналогично Home)

#### Вкладка «Аналитика»

**Верхняя часть:**
- Переключатель: Расход / Доход
- Общая сумма: `12 344 ₽`
- Сравнительный текст: «Больше среднего на 2 300 ₽» (сравнение текущего периода со средним)
- Переключатель периода: Неделя / Месяц / Год

**Графики:**
- Bar chart — тренд расходов/доходов по выбранному периоду
- Визуализация распределения по категориям (какая категория какую долю занимает)

**Список категорий:**
- Категория с эмодзи, название, сумма
- Отсортированы по убыванию суммы
- Показывают тренд — рост или снижение расходов в сравнении с предыдущим периодом

### 4.4. Добавление транзакции (Transaction — создание)

**Экран открывается модально (full-screen):**

**Шаг 1 — Ввод суммы:**
- Кнопка закрытия (X) в левом верхнем углу
- Переключатель: Расход / Доход (сегментированная кнопка)
- Поле суммы: `0,00 ₽` (крупный текст по центру)
- Кастомная цифровая клавиатура (numpad): 1-9, запятая, 0, кнопка подтверждения (✓)

**Шаг 2 — Выбор категории (появляется при вводе суммы):**
- В области между полем суммы и клавиатурой отображаются:
  - **Top-5 рекомендованных категорий** — горизонтальный скролл чипов (эмодзи + название)
  - Алгоритм подбора: на основе исторических данных через формулу скоринга (см. раздел 6)
  - Кнопка «Все категории» → раскрывает грид всех категорий (эмодзи + название, 3-4 колонки)
- Пользователь выбирает категорию тапом

**Шаг 3 — Дата и комментарий:**
- Чип с датой: «Сегодня, 3 июня» (по умолчанию — текущая дата)
- **Тап на чип даты** → открывает date picker для выбора произвольной даты (поддержка задней даты)
- Поле комментария (опциональное): текстовое поле для заметки к транзакции

**Подтверждение (кнопка ✓ на numpad):**
- Валидация: сумма > 0, категория выбрана
- Транзакция сохраняется в локальную БД
- Экран закрывается, данные обновляются на всех экранах

### 4.5. Редактирование транзакции (Transaction — редактирование)

- Открывается при тапе на транзакцию из любого списка
- Тот же экран, что и создание, но предзаполнен данными транзакции
- Все поля редактируемы: сумма, тип (расход/доход), категория, дата, комментарий
- Кнопка «Удалить» внизу экрана → диалог подтверждения
- Кнопка сохранения (✓) → обновляет транзакцию в БД

### 4.6. Экран выбора периода (Filter / Calendar)

Отдельный экран, открывается при нажатии на иконку фильтра.

**Быстрые фильтры (горизонтальный скролл чипов вверху):**
- Эта неделя
- Этот месяц
- Этот квартал
- С начала года

При выборе чипа — автоматически подставляются даты «с» и «по».

**Ручной выбор дат:**
- Два поля: «с [дата]» — «по [дата]»
- Скроллируемый календарь по месяцам (Апрель 2024, Май 2024, ...)
- Тап на дату выбирает начало диапазона, второй тап — конец
- Выделение диапазона визуально на календаре

**Кнопки внизу:**
- «Сегодня» — сбрасывает на текущий день
- «Готово» — применяет фильтр и возвращает на предыдущий экран

## 6. Алгоритм рекомендации категорий (Top-5)

При вводе суммы новой транзакции приложение предлагает топ-5 наиболее подходящих категорий.

**Формула скоринга для каждой категории:**

```
score(category, amount) = w1 * frequency_score + w2 * amount_proximity_score + w3 * recency_score
```

Где:
- **frequency_score** = (кол-во транзакций в категории) / (общее кол-во транзакций) — как часто пользователь использует эту категорию
- **amount_proximity_score** = 1 / (1 + |amount - avg_amount_in_category|) — насколько введённая сумма близка к средней сумме в этой категории
- **recency_score** = 1 / (1 + days_since_last_transaction_in_category) — насколько недавно пользователь использовал категорию

**Веса (начальные, можно корректировать):**
- w1 = 0.3 (частота)
- w2 = 0.5 (близость суммы — главный фактор)
- w3 = 0.2 (давность)

Результат: топ-5 категорий с наивысшим score, отсортированные по убыванию.

data class Transaction(
    val id: Long,
    val type: TransactionType,       // INCOME / EXPENSE
    val amount: Double,              // сумма в рублях
    val categoryId: Long,            // ссылка на категорию

    val isDefault: Boolean = true   // предустановленная или пользовательская
)

## 12. Будущие фичи (не в текущем скоупе)

### 12.1. Бэкенд + синхронизация (приоритет — сразу после MVP)

Offline-first архитектура: приложение работает локально, но синхронизирует данные с сервером при наличии сети.

**Принцип работы:**
- При добавлении транзакции — попытка отправить на сервер
- Если сеть недоступна — сохранение локально с пометкой `isSynced = false`
- При следующем запуске / восстановлении сети — синхронизация несинхронизированных записей

**Что потребуется:**
- Бэкенд (API + БД) — Ktor/Spring + PostgreSQL или Firebase
- Авторизация пользователей (аккаунты)
- Поле `isSynced: Boolean` и `serverId: String?` в локальной модели транзакции
- SyncManager / SyncWorker для фоновой синхронизации
- Конфликт-резолюшн стратегия (last-write-wins или merge)

**Подготовка в MVP (уже заложена):**
- Repository-паттерн позволяет подменить `LocalTransactionRepository` на `SyncedTransactionRepository` без изменений в фичах
- UseCase-слой не зависит от источника данных

### 12.2. Остальные фичи

- **Freemium + подписка**: монетизация через платные функции
- **Импорт CSV**: загрузка банковских выписок
- **Повторяющиеся транзакции**: автоматическое создание по расписанию
- **Предстоящие платежи**: запланированные траты
- **Уведомления**: напоминания о бюджете / лимитах
- **Экспорт данных**: выгрузка в CSV/PDF
